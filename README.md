## 四、人机协同三反思

> 以下反思基于本次实验**真实发生的踩坑与自愈过程**记录，非模板套话。

### 反思一 · 意图清晰度反思

**问题现场：**

在任务二首轮生成 MVP 时，我第一次给出的提示词只有一句话式的目标描述，**只写了“做一个单摆模拟器”**，缺少【技术约束】与【验收标准】两项要素。AI 交回的结果虽然能动，但存在三个偏差：

1. 用了 CDN 引入的第三方动画库，违反了“纯原生 Canvas、不引用外部库”的工程要求；
2. 背景是浅色，与实验要求的深灰科技色 `#1a1a24` 不符；
3. 摆球没有发光光效，视觉质感达不到验收标准。

**根因分析：**

回看当时的提示词，缺失的正是**约束（Boundary）**与**验收标准（Acceptance）**：
- 没有写“单文件 / 纯原生 / 不引用外部库”，AI 就默认选择它认为更省事的工程方案；
- 没有写“背景深灰 #1a1a24 / 摆球发光”，AI 就无法猜测视觉规格，只能走默认样式；
- 没有写“双击打开即可流畅摆动”，AI 没有明确的“交付完成”判据。

**我如何补齐：**

改用课程强调的**黄金三角四段式**（角色 + 目标 + 约束 + 验收标准）重写提示词：

```
【角色】你是一位资深前端可视化与物理仿真工程师。
【目标】创建单个完整的 index.html，实现带物理简谐振动的单摆模拟器。
【技术约束】
  - 单文件 index.html，纯原生 HTML5 Canvas 绘制，不引用外部库；
  - 背景为深灰科技色 (#1a1a24)，摆球带有微弱发光光效；
  - 初始参数：摆长 L=200px，重力 g=9.8，初始摆角 45 度；
  - 使用 requestAnimationFrame 驱动物理计算与动画循环。
【验收标准】浏览器双击打开即可流畅左右摆动。
```

补齐后一次通过，三条偏差全部消除。**结论：约束是“下限”，验收标准是“判据”——两者缺一，AI 就会按自己的默认偏好发挥。**

### 反思二 · 闭环控制反思

**问题现场（任务四）：**

在故障演练页点击“重置摆动”按钮，控制台抛出：

```
Uncaught ReferenceError: resetAnimation is not defined
    at HTMLButtonElement.onclick (index.html:125:46)
```

**我是如何定位问题的：**

我没有用“怎么坏了，重写一遍”这类**情绪化噪声反馈**，而是走了**证据驱动排错**的三步：

1. **调出控制台**：按 `F12` → Console，拿到完整红字堆栈；
2. **锁定位置**：堆栈明确指出 `index.html:125:46`，即按钮的 `onclick="resetAnimation()"`；
3. **交叉验证**：在源码里搜索 `resetAnimation`——只有第 125 行的调用处，没有任何定义处；而真正实现复位逻辑的函数名叫 `resetSimulationState()`。

**AI 的修复方案，我是否看懂了：**

看懂了，而且这是一个非常典型的 **JavaScript 作用域/命名不匹配**问题，与物理公式无关：

- HTML 的 `onclick="resetAnimation()"` 是**全局作用域**调用，浏览器会在 `window` 上查找 `resetAnimation`；
- 源码里定义的是 `resetSimulationState`，从未定义过 `resetAnimation`，因此运行时 `ReferenceError`；
- 修复有两条路径：**(a)** 把按钮的 `onclick` 改成 `resetSimulationState()`；**(b)** 把函数重命名为 `resetAnimation`。二者等价，核心是**调用点与定义点的标识符必须一致**。

我在这个案例上还额外验证了一件事：**这类错误不会导致动画停滞**——因为 `resetSimulationState` 所在的 `<script>` 早已执行完，报错只发生在点击的那一刻；页面上的单摆其实一直在正常摆动。这说明**“看起来还在动”不等于“没有 Bug”**，必须以控制台报错为准，这正是证据驱动排错存在的意义。

修复后控制台 0 报错，重置功能恢复正常。

### 反思三 · 主体地位确认（HOTL）

**作为人在回路之上（HOTL）的产品总设计师，今天这些决策由我决定：**

| 决策类别 | 我的决策 |
| :--- | :--- |
| 物理规格 | 摆长默认 200px、重力 9.8、初始摆角 45°、阻尼 0.002 |
| 交互边界 | 三个滑块的取值范围（100~350 / 1~25 / 0.000~0.010） |
| 视觉标准 | 深灰科技色 #1a1a24、摆球发光、青色高光点 |
| 验收判据 | “双击打开即可流畅摆动”“拖动滑块即时响应”“控制台 0 报错” |
| 迭代节奏 | 拒绝大爆炸，先动起来 → 再交互 → 再排错 → 再进阶 |
| 质量裁决 | 每一轮我亲自在浏览器里看效果、按 F12 查报错，判定是否通过 |

**由 AI 完成的重复劳动：**

- 逐行书写 HTML/CSS/JS 语法，包括 Canvas 绘制路径与 `requestAnimationFrame` 循环骨架；
- 把物理微分方程 α = −(g/L)·sin(θ) − k·ω 翻译成可执行代码；
- 补齐滑块事件监听、数值标签格式化、毛玻璃面板样式等样板代码；
- 提供 RK4 四阶数值积分的实现与双摆方程的展开；
- 提供 `localStorage` 读写与场景平滑过渡的实现。

**结论：** 我的核心工作是 **提需求、设边界、看效果、给反馈**——即定义“做什么、做到什么程度、算不算合格”；AI 负责把这些确定性意图翻译成语法正确的代码。**实验全程我没有手写一行纯语法代码，但我决定了每一行的存在理由。**这就是人在回路之上的主体地位。
